# Cheems 翻译移动端

Android 原生原型，使用手机上现有的输入法。用户主动允许并选定目标 App 后，通过 Android 无障碍服务监听当前可访问的输入框，在屏幕上显示不接收触摸的翻译浮层。

目前优先验证 Android 权限、微博输入框可读性和触摸穿透，再扩充界面功能。iOS 的平台差异见 [`docs/移动端技术栈与可行性分析.md`](docs/移动端技术栈与可行性分析.md)。

## 打开和构建

用 Android Studio 打开 `androidApp` 目录，等待 Gradle 同步后运行 `app` 配置。

需要 Android SDK 36、JDK 17 或更新版本。可运行 `androidApp/gradlew.bat assembleDebug` 构建调试版，APK 位于 `androidApp/app/build/outputs/apk/debug/app-debug.apk`。

当前最低支持 Android 9（API 28）。已在本机雷电模拟器的 Android 9 / x86_64 环境安装并启动；实际手机和微博尚未验证。

## 首次使用

1. 安装并打开 Cheems 翻译。
2. 首次启动时阅读隐私说明并同意。
3. 打开“翻译接口与模型”，新增 AI 模型或通用 HTTP 接口，填写完整连接信息并勾选当前要使用的档案。本地 Ollama 的 API Key 可留空。
4. 在“监听的应用”页选择要使用的 App（例如微博）；在“提示词管理”中选择提示词，并通过主页面开关决定是否启用。
5. 需要朗读时，在“语音模型”页配置 AI 或 HTTP 语音服务，并打开主页面的实时语音开关。
6. 开启实时翻译，点击“去开启”并在 Android 无障碍设置中开启 Cheems 服务。
7. 返回目标 App，进入可编辑输入框并输入文字。停顿或输入常见标点后，译文会显示在输入框附近；浮层不接收触摸，原输入内容不会被改写。

若目标 App 使用不可访问的自绘输入区域，无障碍服务可能无法读取其中的文本。首版尚未在微博真机上验证。

## 本地 Ollama

本机 Ollama 可使用 `hy-mt2:1.8b-q4km`。手机必须能访问运行 Ollama 的电脑，并将电脑上的服务端口转发/开放给手机；模拟器可用 ADB reverse 将模拟器请求转到电脑。接口地址应填写手机可访问的地址并以 `/v1` 结尾，例如 `http://<电脑局域网地址>:<端口>/v1`。Ollama 通常不需要 API Key。不要把 `127.0.0.1` 当成电脑地址直接填在实体手机上，因为它会指向手机自身。

“关于”页显示当前版本、开发者与社区信息，并提供QQ群入口。

## 原型边界

- 目前仅 Android。
- 接口使用 OpenAI 兼容的非流式 Chat Completions 请求。
- 用户输入仍由现有键盘处理；译文展示在不可点击浮层中。
- 无障碍服务只读取用户选择的 App 与当前可访问编辑控件；密码输入会跳过。
- 不记录原始输入文本，也不自动改写或发送目标 App 内容。
- Android App 或 ROM 若不暴露输入框可访问文本，该输入框暂时不能自动翻译。
